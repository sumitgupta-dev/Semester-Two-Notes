Database Systems (Unit 2) Summary

Course: DCA1208 - Database Management System | Semester: 2

1. Introduction & Objectives

A Database Management System (DBMS) is software that facilitates the creation, maintenance, and use of databases, ensuring data consistency, security, and concurrent access. This unit explores the various types of database systems to understand how data is organized, stored, and managed across different applications.

Objectives:

  • Identify the Types of Database Systems
  • List the Advantages and Disadvantages of DBMS
  • Outline applications for different types of Database systems

2. Types of Database Systems

2.1 Hierarchical Databases

Organizes data in a tree-like structure (parent-child relationships). Each child has a single parent, but a parent can have multiple children (1:Many). Fast for specific queries but rigid.

Examples: IBM IMS, Windows Registry.

2.2 Network Databases

Uses a graph-like structure where records can have multiple parents and children (Many:Many). More flexible than hierarchical but complex to manage.

Examples: Integrated Data Store (IDS), Raima Database Manager.

2.3 Relational Database Management Systems (RDBMS)

Organizes data into structured tables (rows and columns). Enforces schema, uses SQL, and follows ACID properties for reliable transactions.

Examples: MySQL, PostgreSQL, Oracle, MS SQL Server.

2.4 Centralised Database Systems

All data is stored and managed in a single location/server. Ensures data consistency and simplified management but faces scalability challenges and single-point-of-failure risks.

2.5 Distributed Databases

Data is stored across multiple physical locations. Offers high availability, fault tolerance, and geographical distribution. Scales horizontally.

Examples: Google Spanner, Amazon Aurora.

2.6 Object-Oriented Databases (OODBs)

Stores data as objects (encapsulating attributes and methods). Supports complex data structures like inheritance and polymorphism, integrating closely with OOP languages.

Examples: db4o, ObjectDB.

2.7 NoSQL Database Systems

Designed for large-scale data and real-time web apps. Schema-flexible and horizontally scalable.

  • Document Stores: MongoDB (JSON-like)
  • Key-Value Stores: Redis, DynamoDB
  • Column Family Stores: Cassandra, HBase
  • Graph Databases: Neo4j

3. Advantages & Disadvantages of DBMS

Advantages

  • Data Sharing: Controlled access for multiple users/apps.
  • Reduced Redundancy: Centralized control avoids data duplication.
  • Data Integrity: Ensures accuracy and consistency.
  • Data Security: Protects confidential data via authentication.
  • Conflict Resolution: DBA manages conflicting requirements.

Disadvantages

  • Complexity & Cost: High initial cost and requires expertise.
  • Security Concerns: Centralized data is a prime target for breaches.
  • Data Integrity Risks: Vulnerable to hardware/human errors.
  • Backup Complexity: Complex recovery strategies needed.
  • Resource Consumption: High CPU and memory usage.

4. Key Terms (Glossary)

DBMS
Software that facilitates the creation, maintenance, and use of databases.
ACID
Atomicity, Consistency, Isolation, Durability - ensures reliable transactions.
RDBMS
Relational Database Management System - organizes data into tables with rows/columns.
SQL
Structured Query Language - used for managing and manipulating relational databases.
Normalisation
Organizing data to reduce redundancy and improve integrity.
MongoDB
A NoSQL document-oriented database storing JSON-like data.
DBA
Database Administrator - manages, secures, and maintains databases.
